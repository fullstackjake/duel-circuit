## 5. Findings (none blocks the commit)

1. **"Choose how to save, then leave." can't be seen (CONFIRMED, both sizes).** Reproduce: change a deck so most of it
   is replaced, press Back, then Save. Save's bar opens over the status line, and the status is set under it
   (`DeckEditor.Leave.cs:110`). The player gets no word that the leaving was dropped. When they choose in the bar, the
   status is overwritten. `-editorcheck` passes because it reads `DebugDeck.status`, not the screen. Low to medium.
2. **Picking a list by hand doesn't mark the deck unsaved (CONFIRMED by code).** `CycleBanlist` sets `_deckListPicked`
   but never calls `MarkDirty` (`DeckEditor.cs:3318-3326`). Pick Goat for a saved free-play deck and press Back: there's
   no dot and no question, so the pick is lost. The deck reopens under its old note or the newest TCG list. Save does
   write the note if pressed (`NoteListPick`). The spec doesn't say a pick is a change, so this is a design gap, not a
   spec break. Low.
3. **One long search label gives "On: …" (CONFIRMED, awkward run q7).** With a 200-character box and 0 results, the
   note reads "On: …" with no label. The chip wraps into two tiny lines inside its pill. `FitTwoLines` drops whole labels
   and never shortens one. Cosmetic.

Smaller notes, all PLAUSIBLE by code:

- The leave title is best-fit 14 to 22 px in a 504x34 box with Wrap and Truncate. A name over about 140 characters would
  lose its end (and the "?") silently. Deck names have no length limit.
- `/` is read as `Key.Slash`, a physical key. On non-US layouts that key types something else (e.g. "-" on German), and
  `GuardSlash` only takes out a "/".
- Two doc comments still cite the old signature `CardSearch.Find(string, SearchMode, string, int, bool)`
  (`DeckEditor.Filters.cs:20, 286`).

Seen but as specified:

- A quoted `"destroy all"` keeps the old order (Level 12 first: Drytron Meteonis Quadrantids...). The unquoted search now
  ranks better than the quoted one.
- The owner's note-less campaign decks now read illegal in free play. Legendary Dragons opens under 2026.10 TCG with
  Pot of Greed and Heavy Storm Forbidden.
- With alternate-art codes, "Apollousa, Bow of the Goddess belongs in the Extra Deck." is listed twice (60-card run). This
  is old behaviour of the problem list, not of this change.

## 6. Steps that could pass with their feature broken, or assert less than the spec

`-editorcheck` (`DuelController.EditorCheck.cs`):

1. "the built-in historic deck abc opens under its era" (line 244) would pass on HEAD too: era lists predate this change.
   It is a regression guard, though the spec says each step fails on today's code.
2. "Don't save leaves... no recovery file" (349) and "the next opening offers nothing back" (353) never check that a
   recovery file existed first. HEAD's `Close()` also clears it when dirty. The New step (380) does check
   `recoveryBefore`.
3. "/ isn't typed into it" (488) can't fail: the test keyboard makes no text events, so no "/" ever reaches the field.
   "Its text selected" (spec D) is never asserted.
4. "/ typed in the deck name is a slash there" (503): the check puts the "/" in itself with `ProcessEvent`. The part that
   bites is `!DebugSearchHasKeyboard`.
5. Spec D says Ctrl/Cmd+S works while a text field has the keyboard. Nothing tests it in a normal field (deck name or
   search). Only Save's bar is tested, and there it must not save.
6. Under the question, Delete and Backspace act on a focused result (D/D/D/D, result 21), where they do nothing anyway.
   The arrows and Page Down carry that step.
7. Not covered at all: Delete's "click Delete again" question (spec A); a Ban Pass card keeping its gold P unless a problem
   names it (E); Extra then Side order for a problem click (E: only a Main copy is clicked); the "...and N more" line
   staying plain (E); the genre and archetype status lines' real count (C).
8. Problem links, underline, ring, badges and the dot are read from the editor's own state (`DebugProblemLinks`,
   `DebugRing`, `DebugUnsavedMark`), not pixels. The click and hover go through the real raycast, though, and the
   screenshots above show they draw.

`-searchcheck`: "Looking in: Favorites." and the empty-Favorites note have no screenshot. The page label "first 2,000"
and the count are label text, which the screenshots confirm.

`-focuscheck`: the G3 strip step reads `DebugMoreStrip` (shown, 16 px, opaque), not pixels; the screenshot confirms it.
G2 reads the ring state; `hand-open.png` confirms it.

`--card-search-test`: the "today's order" comparisons (`Today(q)` = the same query passed as filters) run the new code
against the new code. They prove the no-phrase path is unchanged only if the filter path is. My old/new build in
section 2 covers the Trader path and the counts against HEAD directly. The old-query baseline is compared as sets through
`Find(q, All)`, which is the Trader-style call without `exactWords`.

`--deckbuilding-test`: the `NewestTcg` steps are real and would fail on a wrong pick.
