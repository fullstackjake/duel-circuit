## How the owner works

- **"Use recommended agents."** Big pieces go through specialist agents:
  - designers write a spec first (Game Designer, Economy Designer, Narrative Designer);
  - builders work in chunks on disjoint files: engine and data first, then Unity (Unity Architect) and harness
    (Senior Developer) in parallel against its API;
  - then an independent **Code Reviewer**, then a fix round.
- **Commit and push only when the owner says so.** End commit messages with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never commit `vendor/ygopro-core`.
- **Owner decisions:** each spec ends with an "Owner decisions" section, recommendation first. The owner usually
  answers "Accept all"; record it as a "Decided (owner, date)" line in that section.
- **Owner rules (bugs if broken):**
  - CPUs always play their decks at full strength. Tune by deck choice, never by weakening; ban lists bind only the
    player.
  - Every DP change goes through `Profile.Spend`/`Earn` with a ledger kind, and nothing may be DP-positive
    (`--arbitrage` checks it).
  - Old saves must load.
  - Real players' names never appear in the game (deck provenance goes in a SOURCES.md).
  - Characters are original.
- **Reporting style:** short sentences; say what was verified and what wasn't (audio is never heard: checks run muted).
